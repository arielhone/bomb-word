## מהלך המשחק

1. **מארח פותח חדר** ומקבל קוד בן 4 אותיות ו-QR. השחקנים נכנסים מהטלפון עם שם. אפשר לפתוח את החדר גם **ממסך תצוגה** (לפטופ או טלוויזיה): המסך הוא המארח, מציג את הניקוד ואת מי שמחזיק את הפצצה, ולא משחק בעצמו.
2. **קבוצות:** המארח לוחץ "ערבב", או גורר שחקנים בין העמודות. הקשה על שחקן מעבירה אותו לקבוצה השנייה. כל שחקן לוחץ "אני מוכן". הלחיצה מפעילה את הצליל ומונעת מהמסך להיכבות.
3. **סבב:** מילה אקראית מופיעה **רק** בטלפון של מי שמחזיק את הפצצה. השחקן מסביר לקבוצה שלו בלי להגיד את המילה. כשהקבוצה מנחשת, הוא לוחץ **"נוחש!"** והפצצה עוברת, עם מילה חדשה, לשחקן הבא **מהקבוצה היריבה**. "דלג" מחליף מילה בלי להעביר את הפצצה.
4. **טיימר נסתר**: בין 40 ל-90 שניות כברירת מחדל, והמארח יכול לבחור טווח אחר בלובי: קצר (20–45), ארוך (60–120) או ארוך מאוד (90–180). עם יותר שחקנים כדאי טווח ארוך יותר, כדי שהפצצה תספיק להסתובב. אף אחד לא רואה כמה זמן נשאר. התקתוק מאיץ ככל שהסבב נמשך.
5. **בום:** בכל הטלפונים בבת אחת יש צליל פיצוץ, רטט והבזק אדום. באייפון, שלא תומך ברטט, ההבזק חזק יותר. **הקבוצה היריבה** לזו שהחזיקה את הפצצה מקבלת נקודה.
6. מסך תוצאות מראה את המילה שהתפוצצה. הקבוצה הראשונה שמגיעה ליעד מנצחת: 7 נקודות כברירת מחדל, ואפשר לבחור 5, 10 או 15.

**נגד רמאות:**
- **תמיד:** אחרי כל "נוחש!", המילה שנוחשה מופיעה לכמה שניות בכל הטלפונים ובמסך התצוגה, למשל "✅ נוחש: פלאפל". הקבוצה היריבה יושבת באותו חדר, אז מי שלוחץ "נוחש!" בלי שניחשו נחשף מיד. במסך התוצאות מופיעה רשימת כל המילים שנוחשו בסבב.
- **ערעור (אופציה שהמארח מפעיל בלובי):** במשך 5 שניות אחרי "נוחש!", מי שבקבוצה שקיבלה את הפצצה יכול ללחוץ "🚫 לא נוחש!". הפצצה חוזרת למי שהעביר, עם מילה חדשה, והמילה מסומנת כמחוקה ברשימה. מותר ערעור אחד לכל קבוצה בכל סבב.

**סדר התורות:** כל קבוצה מתקדמת בסבב משלה, והתורות מתחלפים בין הקבוצות: א1, ב1, א2, ב2... גם הקבוצה שפותחת את הסבב מתחלפת בכל סבב. שחקן מנותק מדולג.

## ארכיטקטורה

אין שרת משלנו. Realtime Database משמש בבת אחת כמסד הנתונים, כערוץ הסנכרון וכשכבת ההרשאות. **הדפדפן של המארח הוא השופט:** הוא מגריל את הפתיל, חושף את רגע הפיצוץ ומחלק נקודות. אם המארח נעלם, השחקן המחובר הוותיק ביותר לוקח את התפקיד אחרי 4 שניות.

### מבנה הנתונים

```
rooms/{CODE}
  meta      { hostUid, phase: lobby|playing|results|over, target, cats{}, point{round,team} }
  players/{uid}  { name, team: A|B, order, joinedAt, online, ready, spectator? }
  scores    { A, B }
  game      { round, startedAt, startTeam, holder, team, seq, ptr{A,B}, passedAt,
              last{by, w?, appeal?}, log{s1:{w,by,t,x?}}, appealed{A?,B?}, explodeAt?, boom?, word? }
  used/{wordKey}: true          מילים שכבר יצאו בחדר (רק המפתח)
fuses/{CODE}  { round, ms }     הפתיל הסודי. אף לקוח לא יכול לקרוא אותו
```

### סנכרון הפיצוץ

- כל הזמנים נשמרים בשעון השרת (`ServerValue.TIMESTAMP`). כל לקוח מתקן את השעון שלו לפי `.info/serverTimeOffset`, ולכן לא סומכים על השעון של אף טלפון.
- אורך הפתיל נשמר ב-`fuses/{CODE}`, שנעול לקריאה. 3 שניות לפני הסוף המארח כותב את `game.explodeAt`, וכל הטלפונים מתזמנים את הפיצוץ לאותו רגע בשעון השרת. בבדיקה עם 5 טאבים, כל הטלפונים התפוצצו בהפרש של 5ms זה מזה.
- **קצב התקתוק** מחושב לפי הזמן **שעבר** מתחילת הסבב, לא לפי הזמן שנשאר, ולכן הוא לא מסגיר את אורך הפתיל. ב-3 השניות האחרונות הקצב קופץ לקצב מטורף.
- אם המארח לא מחובר, כל שחקן מנסה לרשום את הפיצוץ. ה-rules מאשרים את הרישום רק אחרי שהפתיל **באמת** נגמר, כי הם יכולים לקרוא את `fuses` גם כשהלקוח לא יכול.

### העברת הפצצה

`runTransaction` על `game`. הטרנזקציה בודקת שאני המחזיק ושה-`seq` לא השתנה, ולכן לחיצה כפולה על "נוחש!" מעבירה פעם אחת בלבד. גם השרת אוכף את זה:

| כלל | למה |
|---|---|
| רק המחזיק (או המארח) מעביר | אי אפשר לחטוף את הפצצה |
| `seq` עולה ב-1 בדיוק | לחיצה כפולה או בקשה ישנה נדחות |
| רק לשחקן מהקבוצה היריבה | אי אפשר להעביר לחבר לקבוצה |
| רק לפני שהפתיל נגמר | מסירה "ברגע האחרון" שהגיעה לשרת אחרי הפיצוץ נדחית |
| ערעור: רק כשהאופציה פעילה, רק מהקבוצה שקיבלה, תוך 5 שניות (ועוד שנייה חסד), פעם אחת לקבוצה בסבב, והפצצה חוזרת רק למי שהעביר | אי אפשר לערער סתם, לערער שוב ושוב, או "לשלוח" את הפצצה למישהו אחר |

**ניתוק:** הנוכחות מנוהלת עם `onDisconnect`. אם המחזיק סוגר את הטאב או מאבד חיבור, המארח מעביר את הפצצה לבא בתור אחרי 3 שניות. ההמתנה הקצרה מונעת העברה כשמישהו רק מרענן.

### מודל אבטחה ([`database.rules.json`](database.rules.json))

- כל שחקן כותב רק את הרשומה של עצמו, ולא יכול לשנות לעצמו קבוצה או ניקוד.
- רק המארח משנה שלבים, ניקוד וקבוצות, ורק הוא מוחק את החדר.
- יוצרים חדר רק בקוד פנוי, ואי אפשר לדרוס חדר קיים.
- המילה עצמה לא נשמרת ב-DB בזמן הסבב. היא מוגרלת בטלפון של המחזיק, ולכן אי אפשר לגלות אותה מטלפון אחר.

> [!NOTE]
> המארח הוא זה שמגריל את הפתיל, ולכן מארח שמשתמש ב-DevTools יכול לדעת מתי יהיה הפיצוץ. בין חברים זה בסדר. הגנה מלאה דורשת Cloud Functions, שמחייבות את תוכנית Blaze.
>
> חדרים לא נמחקים אוטומטית (ב-Realtime Database אין TTL). מארח שיוצא כשאין אף אחד אחר מחובר מוחק את החדר.

## הקמה (פרויקט Firebase חדש)

1. [Firebase Console](https://console.firebase.google.com) ← **Add project**. התוכנית החינמית Spark מספיקה.
2. **Build → Authentication** ← Get started ← Sign-in method ← הפעל **Anonymous**.
3. **Build → Realtime Database** ← Create database ← בחר אזור (מומלץ `europe-west1`) ← **Locked mode**.
4. **Project settings** ← Your apps ← **Web app** (`</>`) ← העתק את `firebaseConfig` אל [`firebase-config.js`](firebase-config.js). חשוב שיהיה בו גם `databaseURL`.
5. עדכן את מזהה הפרויקט ב-[`.firebaserc`](.firebaserc), ופרוס את כללי האבטחה:

```bash
npm i -g firebase-tools
firebase login
firebase deploy --only database
```

### פריסה ל-GitHub Pages

1. דחוף את הריפו ל-GitHub.
2. **Settings → Pages** ← Source: *Deploy from a branch* ← `main` / `(root)`.
3. **חשוב:** ב-Firebase Console ← Authentication ← Settings ← **Authorized domains**, הוסף `<המשתמש-שלך>.github.io`. בלי זה ההתחברות האנונימית תיכשל.

> [!TIP]
> `apiKey` שב-`firebase-config.js` אינו סוד, הוא רק מזהה את הפרויקט. מה שמגן על הנתונים הם ה-rules.

## פיתוח ובדיקות

### הרצה מקומית מול האמולטור (בלי לגעת בפרויקט האמיתי, דורש Java)

```bash
firebase emulators:start --only auth,database --project demo-bomb-word
python -m http.server 8123          # בטרמינל נוסף, מתוך תיקיית הפרויקט
```

פותחים את `http://127.0.0.1:8123`. מ-localhost המשחק מתחבר לאמולטור אוטומטית. כדי לעבוד מ-localhost מול הפרויקט האמיתי, מוסיפים `?live=1`.

### בדיקה עם כמה "שחקנים" על מחשב אחד

כל **פרופיל דפדפן** מקבל משתמש אנונימי משלו. טאבים באותו חלון **חולקים** משתמש, ולכן הם ייחשבו לאותו שחקן. כדי לדמות כמה שחקנים:

| שחקן | איך |
|---|---|
| מסך תצוגה / מארח | חלון Chrome רגיל ← "📺 פתח חדר ממסך תצוגה" |
| שחקן 1 | חלון גלישה בסתר של Chrome (Ctrl+Shift+N) |
| שחקן 2 | Edge, או חלון InPrivate שלו |
| שחקן 3 | Firefox, או חלון פרטי שלו |
| שחקן 4 | פרופיל Chrome נוסף (סמל הפרופיל ← Add), או הטלפון שלך ברשת המקומית |

> חלונות הגלישה בסתר של אותו דפדפן חולקים ביניהם מצב אחד. לכן לכל שחקן נוסף צריך דפדפן או פרופיל אחר.
> כדי לפתוח את המשחק מהטלפון כשהוא רץ מקומית, הריצו את השרת עם `--bind 0.0.0.0` וגלשו ל-IP של המחשב. שימו לב: מחוץ ל-localhost המשחק מתחבר לפרויקט האמיתי, לא לאמולטור.

**תרחיש בדיקה מומלץ:**

1. במסך התצוגה: פתחו חדר. בכל חלון שחקן: הקלידו את הקוד ושם, ולחצו "אני מוכן". צריך לפחות 2 שחקנים בכל קבוצה.
2. במסך: "🔀 ערבב קבוצות". נסו גם לגרור שחקן לקבוצה השנייה או להקיש עליו.
3. "💣 התחל משחק". **רק** בחלון אחד אמורה להופיע מילה. בשאר מופיע "הפצצה אצל X".
4. לחצו "נוחש!" פעמיים מהר. הפצצה אמורה לעבור פעם אחת בלבד, לשחקן מהקבוצה השנייה.
5. בלובי הפעילו "ערעור". אחרי "נוחש!" כל החלונות מציגים את המילה, ובקבוצה שקיבלה מופיע "🚫 לא נוחש!". לחיצה עליו מחזירה את הפצצה, והכפתור נעלם אחרי 5 שניות.
6. **סגרו** את החלון של מי שמחזיק את הפצצה. אחרי כ-3 שניות היא אמורה לעבור לבא בתור.
7. חכו לפיצוץ (בטווח שנבחר בלובי, למשל "קצר": 20–45 שניות): הבזק וצליל בכל החלונות יחד, ואחר כך מסך תוצאות עם המילה ו-+1 לקבוצה היריבה.
8. סגרו את מסך התצוגה (המארח) באמצע סבב. אחרי כ-4 שניות שחקן אחר יקבל 👑, והסבב יסתיים כרגיל.

```
├── index.html            מעטפת הדף

```

### הוספת מילים

ב-[`words.json`](words.json) כל קטגוריה בנויה כך: `{ "id", "name", "emoji", "words": [...] }`. אפשר להוסיף מילים לקטגוריה קיימת או ליצור קטגוריה חדשה, והיא תופיע אוטומטית בבחירת הקטגוריות בלובי. מוסיפים מילים **רק בסוף** הרשימה, כי המפתח של כל מילה הוא המיקום שלה בקטגוריה.
